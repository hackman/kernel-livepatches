What this is

The mitigations ship in two flavours(livepatch and/or ftrace) so you can pick the right trade-off for your kernel configuration:

⚙

ftrace flavour

Low-config dynamic ftrace with IPMODIFY. Redirects a function at its fentry site. Works wherever DYNAMIC_FTRACE_WITH_REGS is enabled — no livepatch infrastructure needed. Useful for older kernels.

🔑

livepatch flavour

Rides the kernel's CONFIG_LIVEPATCH consistency model. Cleaner semantics, safe transition, and able to target not-yet-loaded modules. The preferred mechanism on modern distro kernels.

🛡

surgical CVE fixes

CVE modules reimplement the exact upstream fix — the whole target function body, with only the security hunk changed — so behaviour matches mainline byte-for-byte except for the bug.

Auto-load on boot

Drop any livepatch=Y module into /lib/modules/$(uname -r)/livepatches and the bundled systemd service applies them on boot — serialized so each patch's transition completes before the next is enabled (the kernel allows only one livepatch in transition at a time).

make install-autoload     # stage .ko + install script + enable service
make autoload-now         # apply immediately, no reboot
Heads up: these are offensive-security / defensive research tools. They taint the kernel (TAINT_LIVEPATCH), require root, and target specific kernel versions. Read each module's header and test on a matching kernel before production use.

Requirements

  • x86_64; Linux 4.11+ (each source selects the right API via LINUX_VERSION_CODE).
  • Kernel build tree at /lib/modules/$(uname -r)/build.
  • livepatch modules: CONFIG_LIVEPATCH=y; ftrace modules: CONFIG_DYNAMIC_FTRACE_WITH_REGS=y.
